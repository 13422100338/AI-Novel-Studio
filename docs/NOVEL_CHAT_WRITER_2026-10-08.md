# 聊天驱动正文写作与无控制台启动修复

工作分支：`codex/novel-chat-writer`，基线 `c06f036`。所有源代码修改在独立集成工作树完成。

## 本次启动错误

桌面启动器使用 `pythonw.exe`，其 `sys.stdout`、`sys.stderr` 为 `None`。小说 MCP 的 Uvicorn 默认日志格式器会自动调用 `sys.stdout.isatty()`，产生 `Unable to configure formatter 'default'`。这发生在小说 MCP 初始化阶段，与作品正文或 ChatGPT 登录无关。

`novel_server.py` 显式设置 `use_colors=False`，保留鉴权、回环地址、资料工具和错误过滤。修复独立提交为 `7baa952`。

新增回归测试在标准输出、错误流均为 `None` 时初始化 MCP、建立真实客户端连接并读取临时小说正式正文。测试还重置 Uvicorn 的全局格式器设置，避免之前的服务器实例掩盖问题。

## 写作工作流

作者在右侧聊天提出正文创作、续写或修改任务。Codex 读取当前小说、章要求与必要资料，将目标、接续位置、禁止改动和有来源标注的素材整理为本次写作要求，再调用 `generate_novel_draft`。

正文始终由设置页的独立写作模型生成。服务复用现有 `ProjectGenerationSession`、上下文预算、生成记录及检查点，不引入新的 Agent 循环或数据库迁移。本次聊天要求仅在生成时合并，不覆盖作者已保存的章要求；不存在章要求时使用临时要求，不插入空要求记录。

右侧任务卡片显示准备上下文、模型生成、收到字数和完成状态。完成或中断后可展开、选取或复制候选草稿；不自动采用、保存或覆盖正式正文。模型内容以纯文本显示。

| Before | After | Why |
| --- | --- | --- |
| 中间栏三点菜单与独立生成配置弹窗 | 正文区保留明确的保存和冲突重载入口，生成交给聊天 | 减少分散的操作路径 |
| 独立写作模型未接入生产侧栏 | Codex 通过小说 MCP 调用写作管线 | 保留 Agent 与写作模型独立的设计 |
| 模型、会话占据较多聊天空间 | 模型与会话控件可展开，常用写作动作两行排列 | 给对话与任务卡片更多空间 |
| 相邻栏位紧贴、正文使用无衬线字体 | 米色画布、暖棕强调色、圆角分区与宋体正文 | 接近作者提供的纸张主题参考图 |
| 侧栏初始展开可能不显示 | 初始化时同步可见状态 | 新开窗口即可显示侧栏 |

## 参数与权限

工具只服务于当前打开的小说、当前选中的章节及匹配修订。每轮作者消息最多一次生成，同时最多一项任务。要求限 20000 字，目标为 100–30000 字，输出上限为 1024–32768 tokens；既有模型能力与上下文预算会进一步限制请求。无效布尔值、过期修订、外部章节和已撤销项目不能触发模型。

工具准确声明 `readOnlyHint=False`、`destructiveHint=False`、`openWorldHint=True`。仅对该工具设置 `mcp_servers.novel_workspace.tools.generate_novel_draft.approval_mode=approve`，保留原有只读 Codex 沙箱和其它工具限制。MCP 工具超时为 300 秒；取消会通知正文管线，已收到内容留在候选检查点。

单工具授权和工具超时的配置依据：[官方 Codex 配置参考](https://learn.chatgpt.com/docs/config-file/config-reference)。未改动用户的全局 Codex 配置、模型选择或凭据。

无需桌面控制的复现命令：

```powershell
$env:PYTHONPATH = "$PWD\src"
& '<repo>/.venv/Scripts/python.exe' scripts/validate_chat_writer.py --headless --live
```
