本票在 `codex/novel-chat-writer` 集成分支完成。作者作品、人物资料、数据库结构、写作模型配置和凭据均未修改。

| Before | After | Why |
| --- | --- | --- |
| 人物和时间线行高未包含内边距，姓名挤出卡片 | 人物卡片至少56px，时间线至少48px，实际行高包含文字和内边距 | 长姓名与资料内容不再重叠 |
| 人物详情挤压窄窗口列表 | 宽窗口左右排布，窄窗口上下排布 | 两种窗口宽度下内容均留在页面内 |

## 批量阅读边界

数据通过现有只读 `NovelReadService` 访问。仅允许当前小说正式章节，逐章返回ID、修订、内容哈希、字符范围和正文；读取期间修订变化会拒绝返回。

`offset` 从0开始，`limit` 选择连续范围；`chapter_ids` 选择非连续章节，结果仍按作品顺序。默认选择最多1000章，每批最多100章；默认250000字符，上限300000。响应同时说明作品可用章数与所选范围，不隐藏范围限制。

超过单批容量时返回 `truncated` 和 `next_cursor`，调用者保持选择参数、传入游标续读。测试验证续读没有遗漏或重复字符。Codex 创作会话指令要求多章问题优先使用批量工具，不能把未读部分当成已读。

批量工具的输出预算明确配置为200000 tokens，避免保留原来的小型单章工具输出预算。该值是输出截断预算；能否处理超长作品还受实际 Codex 模型上下文容量限制。不会无限制导入整个磁盘的文件。

## 状态汇总

每轮消息有独立读取汇总，所有小说资料工具都更新该条状态。重复完成通知不重复计数；同章多次读取只计一章。只有正文读取工具增加章数；读取上下文、约束等计为资料查询。开始新消息、切换项目和恢复会话会重置本轮汇总状态，保留历史消息中的旧汇总。

原始章节内容不存进汇总状态，只提取工具身份、执行状态和来源章节ID。模型侧依然收到完整工具结果。失败与停止会结束忙碌状态，保持明确反馈。

## Markdown 显示

复用已安装 Qt 的 GitHub Markdown 方言，不新增依赖。常用标题、加粗、斜体、列表、表格、引用和代码块由原生文本引擎显示；流式更新继续作用于原消息卡片。

原始HTML禁用，图片资源加载禁止；生成的图片标签替换为文字提示，本地文件与脚本链接不保留可点击地址。模型原始文本和用户原始输入不改写，只改变显示投影。富文本文档格式保持稳定，避免切换格式时 Qt 把用户原文反写为HTML。格式结果缓存最多16项，每条最多200000字符。

## 验证

- 人物布局测试先稳定复现13px行高容不下文字，再验证1100与1440窗口中的姓名、长档案、详情与时间线。
- 批量读取测试覆盖34章一批读完、指定范围、非连续选择、来源哈希、续读以及无效/外部章节拒绝。
- 实际 MCP 协议读取、鉴权、无控制台运行与原写作服务保持兼容。
- Qt文本测试验证实际显示的加粗/标题等格式、用户原文、资源限制与流式更新；聊天卡片布局回归通过。
- 真正由后台 `pythonw.exe` 中的 Codex 一次调用批量工具读取临时小说34章。只生成一条汇总：`已读取 34 章内容 · 资料查询 1/1 项 · 读取完成`。正式正文和章要求未改动，也未调用写作模型或联网。

无桌面操作的复现命令：

```powershell
$env:PYTHONPATH = "$PWD\src"
& '<repo>/.venv/Scripts/python.exe' scripts/validate_chat_writer.py --headless --live --read-all
```
