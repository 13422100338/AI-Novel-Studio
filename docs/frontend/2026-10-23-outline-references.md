# 大纲页内引用与助手输入框

本票延续正文 / 大纲 / 笔记三个同级工作区，收起独立的“对应章节”栏，将引用显示在大纲纸面内，并减少助手周围的常驻控件。

## 使用方式

- 在大纲导航中选择事件，点击“关联”可插入正式章节或笔记链接，也可进入原有的关联检查与确认界面。
- 宽阅读区在标题后显示编号链接，用折线连接到右侧留白处的完整章节或笔记标题；窄阅读区改为标题后的完整名称链接。长名称换行显示。
- 章节链接保留项目内的 Markdown 相对路径；笔记使用 `[笔记名称](novel://note/笔记UUID)`。作者仍可编辑、导出大纲源码。
- 点击章节链接打开正式正文，点击笔记链接打开笔记；仅浏览笔记不会将它选入正文模型输入。
- AI 助手输入框内以一个控件显示模型和思考强度，点击向上弹出选择菜单；`/model` 使用同一菜单。输入框左下角“＋”集中提供附件、写作指令和笔记选择。
- 主题与动效开关移入“设置 → 外观与交互”；Token、费用等详情移到左下角“状态”。“新建项目”使用同一主题的对话框，只保留一组取消与创建按钮。
- 移除左侧“旧资料”入口，保留旧项目内容和数据库兼容性。

## 链接与正文创作

为事件关联目标章节后，模型先生成候选；作者采用时才提交该章节的新修订，章节身份不变，因此原链接继续指向更新后的正式正文。生成候选本身不会创建新章节或替作者建立关联。

大纲修改后，已有章节链接保留并进入重新确认流程。正文输入仍须经作者确认，打开链接不等于已向独立正文模型传入材料；笔记原文或要点仍通过既有笔记选择与输入提案交付。

## 实现与边界

`outline_references.py` 根据现有标题、链接索引和项目章节 / 笔记目录构造只读显示数据；`outline_markdown_view.py` 将引用标记附到渲染后的标题，`OutlineReferenceNotes.qml` 负责页内连线与完整标题。文件操作仍由既有 bridge / repository 完成。

只含已识别链接的源码行在阅读副本中移到标题引用处，原文件与版本不变；混合正文、代码块和未识别链接保持显示。内部链接仅接受当前项目登记的章节路径或规范 UUID，不从任意本地路径加载资料。

本票没有数据库迁移，没有替换正文生成流程，也没有修改作者的小说、备份或密钥。

## 验证

75 项相关工作区、Markdown、主题和 Codex 控件测试通过；最后的小幅类型与格式修正后，10 项重叠的桥接 / 页面检查通过。Ruff、四个桥接模块的 MyPy 与 `git diff --check` 均通过。

Windows 原生窗口使用临时小说、模拟模型目录及临时设置文件完成 12 个画面阶段，覆盖章节 / 笔记跳转、模型与强度、材料菜单、状态、新建项目、外观设置，以及 1100 像素窄窗口和恢复宽窗口。QML 警告为零；验证期间大纲内容、正式正文与笔记选用状态保持不变，未调用真实写作模型。

改动保留在 `codex/writing-notes` 工作树，尚未提交或替换桌面旧入口。使用该工作树的 `启动程序.bat` 重启后生效。

## 表格滚动与卷章弹窗修复

使用作者提供的 44,503 字符、191 行表格的大纲原文，在临时项目中复现了向下连续经过表格再向上滚动时的文字空白。修复前 96 个滚动采样中，有 41 个返回视口的文字绘制明显减少；大纲文本始终保留。

当轮尝试将阅读器父级设为 `readerScroll.contentItem`。后续发现这实际是固定视口，会把文字留在滚动内容之外，导致滚动条移动而文字不动。该处理已由下一节的修复替代。

`ContextSidebar.qml` 的新建卷、章弹窗改用现有 `StudioDialog` / `AppTextField` / `AppButton`，移除系统默认取消按钮与自定义按钮叠加的问题。`CodexChoiceBox.qml` 隐藏输入框内选择器的下拉箭头并回收其留白，点击与键盘选择保持可用。

验收勘误：当轮 35 项测试确实通过，但未检查文字在场景中的实际位移。原生窗口的 280 次采样实际停留在同一画面，不能作为滚动成功或表格重绘成功的证据。卷章创建、单一取消按钮、无下拉箭头及原始文件未变的检查仍有效；滚动验收以下一节为准。

相关测试命令：

```powershell
python -m pytest tests/ui_qml/test_outline_workspace_layout.py tests/ui_qml/test_workspace_chrome.py tests/ui_qml/test_codex_compact_picker.py tests/ui_qml/test_outline_page.py -q -p no:cacheprovider
```

## 滚轮、表格绘制与设置入口修正

- `OutlinePage.qml` 恢复 `ScrollView` 直接承载单个 `TextArea` 的结构，由滚动视图把文字放入可移动内容层。引用作为阅读器的子项显示在右侧留白，正文与引用共同决定内容高度。移除固定视口父级和多余容器。
- `outline_markdown_view.py` 的 `prepareTableReader` 仅对含表格的阅读文档关闭 `ItemObservesViewport`，避免向上滚动时富文本表格的局部绘制丢失段落；外层视口继续裁剪。这里使用的是 [Qt 公开的视口标志](https://doc.qt.io/qt-6.10/qquickitem.html#Flag-enum)，没有更换渲染技术栈或修改原文。
- 切回大纲时恢复显示绑定，不再先清空健康的文档，避免长引用区的高度暂时归零而丢失阅读位置。
- `App.qml` 移除左侧导航栏实例，把原有设置操作放在状态栏最右侧的齿轮按钮中，保留悬浮提示、键盘访问和已选状态。

新的滚轮回归在修复前失败：滚动距离已增加 182 像素，文字的场景坐标却保持不变。修复后，阅读页和源码页均验证了向下 / 向上滚轮、文字位移与内容保存；滚动条拖动也必须同时带动文字移动。

验证结果：48 项相关页面、Markdown、工作区、笔记与模型选择测试通过；Windows 原生滚轮用例另行通过。Ruff、渲染桥 MyPy 和差异检查通过。原生完整大纲副本遍历 128 个位置，双向共 256 次，逐次断言实际滚动位置与文字坐标，并比较返回视口的绘制，未发现缺失。另验证了鼠标滚轮、滚动条拖动、1100 像素窄窗口和右下角设置入口；QML 警告为零。原始大纲校验值保持不变，未打开或写入作者数据库。

## 带编号 Markdown 标题的导航定位

实际大纲有 170 个导航条目，旧阅读映射仅匹配到 117 个。`### 1. 一句话故事` 这样的标题在完整文档中保留编号，但旧辅助函数单独渲染 `1. 一句话故事` 时把它识别为列表、丢掉编号，导致 53 个目标位置缺失；点击这些条目后会落到阅读区开头。

本票只修改 `outline_markdown_view.py` 的标题文本解析：Markdown 标题按标题内的行内语法处理，普通编号事件继续按原列表语法处理；目录标题也保留编号。没有改写原文、导航数据或存储格式。

新增两项回归在修复前均失败，分别覆盖编号标题的位置映射，以及实际点击后目标文字应出现在视口顶部附近；同时包含表格、粗体、重复标题和 emoji。修复后 41 项相关 Markdown、页面、工作区和引用测试通过。Windows 原生窗口对完整副本逐项点击全部 170 个条目，并在 1100 / 1600 像素窗口追加 8 次跨位置跳转，共 178 次，均核对选中条目、实际滚动距离和目标文字坐标。QML 警告为零，原始大纲与副本内容保持不变。
